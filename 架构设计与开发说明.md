## 1. 项目概述

### 1.1 定位

本项目是一个**本地大模型工作流编排 MVP**，目标是提供一套可快速扩展的框架，用于：

- 将各类 LLM 能力封装为可插拔的**工具（Tool）**
- 通过 **YAML 配置**将多个工具编排为**工作流（Workflow）**
- 利用 LLM 实现**自动路由（Auto Routing）**：根据输入数据分类并选择对应工作流
- 支持 **RAG 文档问答**、**Excel 自然语言查询**、**旅游标签生成**、**文本纠错**等垂直场景

### 1.2 技术栈

| 层次       | 技术                                           |
|----------|----------------------------------------------|
| 前端 UI    | Streamlit                                    |
| 后端 API   | FastAPI + Uvicorn + Pydantic                 |
| 大模型服务    | Ollama（本地 HTTP API，`/api/chat`、`/api/embed`） |
| 工作流定义    | YAML（PyYAML）                                 |
| 向量数据库    | ChromaDB（本地持久化）                              |
| 数据处理     | pandas + openpyxl                            |
| 文档解析     | pypdf                                        |
| HTTP 客户端 | httpx（异步）、requests（UI 同步调用）                  |

### 1.3 核心特性

- **工具即插即用**：在 `tools.py` 中用 `@register` 装饰器注册函数，UI 自动展示
- **工作流配置化**：在 `workflows/*.yaml` 中新增步骤即可扩展，无需修改代码
- **上下文贯通**：每个工具的输出合并进 `context`，后续工具可直接引用
- **条件分支**：YAML 中通过 `condition` 表达式控制节点是否执行
- **自动路由**：`router.py` 调用 LLM 对输入分类，`_pick_workflow` 选择最匹配的工作流
- **完全本地化**：模型推理、向量存储、数据处理全部在本机完成

## 4. 核心模块详解

### 4.1 `config.py` — 全局配置

集中定义所有常量，并在导入时自动创建必要目录。

| 配置项                  | 默认值                                | 说明                       |
|----------------------|------------------------------------|--------------------------|
| `OLLAMA_URL`         | `http://127.0.0.1:11434/api/chat`  | 对话补全接口                   |
| `DEFAULT_MODEL`      | `qwen3-coder:30b`                  | 默认生成模型（备选 `llama3.1:8b`） |
| `REQUEST_TIMEOUT`    | `120.0`                            | LLM 请求超时（秒）              |
| `EXCEL_WORKDIR`      | `data/excel`                       | Excel 文件根目录              |
| `EXCEL_PREVIEW_ROWS` | `20`                               | Excel 结果预览行数             |
| `EMBED_MODEL`        | `nomic-embed-text`                 | 嵌入模型                     |
| `EMBED_URL`          | `http://127.0.0.1:11434/api/embed` | 嵌入接口                     |
| `RAG_DOCS_DIR`       | `data/rag_docs`                    | RAG 原始文档目录               |
| `CHROMA_DIR`         | `data/chroma_rag`                  | ChromaDB 持久化目录           |
| `RAG_COLLECTION`     | `documents`                        | 向量集合名称                   |
| `RAG_CHUNK_SIZE`     | `500`                              | 文档切分块大小                  |
| `RAG_CHUNK_OVERLAP`  | `80`                               | 切分重叠字符数                  |
| `RAG_TOP_K`          | `5`                                | 默认检索片段数                  |
| `RAG_EMBED_BATCH`    | `32`                               | 批量嵌入大小                   |

### 4.2 `main.py` — FastAPI 应用入口

定义全部 HTTP 端点（详见 [第 8 节](#8-api-接口文档)）。核心逻辑：

- `_pick_workflow(route, workflows)`：按 `data_type_category` → `data_type` → `default` 的优先级选择工作流
- `/run`：根据 `auto_route` 决定是否先调用 `classify_data`，再调用 `execute_workflow` 执行
- 工作流 CRUD 端点通过 `engine.py` 的函数直接读写 YAML 文件

### 4.3 `engine.py` — 工作流引擎

**读取capabilities：**

- `load_workflows()`：扫描 `app/workflows/*.yaml`，兼容两种格式：
    1. 单工作流文件（含 `name` / `description` / `steps`）
    2. 多工作流文件（`workflows: { name: {...} }`）
- `load_workflow_raw(name)`：返回原始 YAML 文本（用于前端编辑器），优先独立文件，回退从多工作流文件中提取

**写入能力：**

- `_validate_yaml(name, content)`：校验 YAML 语法、根节点类型、`name` 一致性、`steps` 非空、工具名是否存在
- `save_workflow_raw(name, content)`：保存到 `{name}.yaml`，并自动从多工作流文件中剔除同名条目以避免重复
- `delete_workflow(name)`：删除独立文件或从多工作流文件中移除条目

**执行能力：**

- `_eval_condition(expr, context)`：用 `eval(expr, {"__builtins__": {}}, context)` 求值条件表达式，异常时返回 `True`
- `execute_workflow(workflow, input_data)`：核心执行循环
    1. 初始化 `context = input_data`
    2. 遍历 `steps`，计算 `condition`（不满足则记录 `skipped` 并跳过）
    3. 合并 `step_inputs = {**context, **with_params}`（`with` 参数优先级更高）
    4. 调用 `tool["func"](step_inputs)`，将 dict 结果合并进 `context`
    5. 记录每步输出/错误到 `steps_log`；工具缺失或异常时 `break`
    6. 返回 `{"context": context, "steps": steps_log}`

### 4.4 `ollama_client.py` — Ollama 客户端

封装两个异步函数：

- `chat(prompt, system, model, json_mode, temperature) -> str`
    - 构造 messages（system + user），可选 `format: json`
    - 使用 `httpx.AsyncClient` 发送 POST 请求，返回 `data["message"]["content"]`
- `embed(text, model) -> list[float] | list[list[float]]`
    - 支持单条文本与批量文本
    - 使用 `trust_env=False` 避免代理干扰
    - 连接失败时抛出带提示信息的异常

### 4.5 `router.py` — 自动路由

- `classify_data(data) -> dict`
    - 从 `data` 中提取 `text` / `body` / `content`（最多 2000 字符）
    - 构造分类 prompt，候选类型：`email`(spam/normal/phishing/support)、`review`(positive/negative/neutral)、`news`(
      finance/tech/sports/entertainment/other)、`other`
    - 调用 `chat(..., json_mode=True)`，解析 JSON；解析失败返回
      `{"data_type": "other", "category": "unknown", "confidence": 0.0}`

### 4.6 `schemas.py` — 请求模型

| 模型                    | 字段                                                                |
|-----------------------|-------------------------------------------------------------------|
| `RunRequest`          | `data: dict`、`workflow: Optional[str]`、`auto_route: bool = False` |
| `ToolRunRequest`      | `inputs: dict[str, Any]`                                          |
| `WorkflowSaveRequest` | `yaml: str`                                                       |

### 4.7 `tools.py` — 工具注册中心

通过 `TOOLS: Dict[str, Dict]` 全局字典管理工具。

- `register(name, description, input_schema, output_schema)`：装饰器，将函数及其元信息注册到 `TOOLS`
- `get_tool(name)`：按名获取工具
- `list_tools()`：返回所有工具元信息（剔除 `func` 字段）
- `_safe_json(raw, fallback)`：JSON 解析失败时返回 fallback 并附带 `_raw` 字段

工具按功能分为 13 大类，共 46 个（原有 30 个 + TASKS.md 扩展 16 个，详见 [第 6 节](#6-工具系统)）。

### 4.8 `rag.py` — RAG 子系统

详见 [第 9 节](#9-rag-知识库系统)。

## 5. 数据流与执行流程

### 5.1 工作流执行流程（`/run`）

```
用户输入
   │
   ▼
RunRequest(data, workflow?, auto_route?)
   │
   ├── auto_route=True ──► classify_data(data) ──► route {data_type, category, confidence}
   │                                                    │
   │                                                    ▼
   │                                          _pick_workflow() 选择工作流名
   │                                                    │
   └── auto_route=False ──► workflow 或 "default" ◄─────┘
                                   │
                                   ▼
                        load_workflows()[name] 加载工作流定义
                                   │
                                   ▼
                     execute_workflow(workflow, data)
                                   │
              ┌────────────────────┼────────────────────┐
              ▼                    ▼                    ▼
        condition 判断       with 参数合并        调用工具函数
              │                    │                    │
              └────────────────────┼────────────────────┘
                                   ▼
                         context 累积 + steps_log 记录
                                   │
                                   ▼
              {"workflow", "route", "result": {"context", "steps"}}
```

### 5.2 上下文传递机制

以内置 `email_support` 工作流为例：

```yaml
steps:
  - tool: summarize_text        # 输出 summary → 写入 context
  - tool: extract_ticket        # 输出 order_id/issue_type/urgency → 写入 context
  - tool: draft_reply           # 从 context 读取 summary 和 text → 输出 reply
  - tool: write_db              # condition: urgency == 'high'，仅高优先级执行
```

每步的 `step_inputs = {**context, **with_params}`，因此**前面步骤的所有输出对后续步骤可见**，而 `with` 中的参数可覆盖
context 中的同名键。

### 5.3 工具组合调用

复杂工具可在内部复用其他工具，例如：

- `summarize_and_translate` 内部依次调用 `summarize_text` 和 `translate_text`
- `correct_text_by_sentence` 按句切分后循环调用 `correct_text`
- `rag_answer_v2` 调用 `rag_rewrite_query` 改写查询，再多路检索并合并

### 6.2 新增工具开发规范

1. 在 `app/tools.py` 中使用 `@register` 装饰器定义异步函数
2. 函数签名为 `async def func(inputs: dict) -> dict`
3. 声明清晰的 `description`、`input_schema`、`output_schema`（字典形式）
4. JSON 解析统一使用 `_safe_json(raw, fallback)` 兜底
5. 新增后无需重启 UI 配置，刷新页面即可在“工具库”标签页看到

示例：

```python
@register(
    name="my_tool",
    description="我的工具说明",
    input_schema={"text": "string"},
    output_schema={"result": "string"},
)
async def my_tool(inputs: dict) -> dict:
    text = inputs.get("text", "")
    result = await chat(f"处理以下文本：{text}")
    return {"result": result.strip()}
```

## 7. 工作流引擎

### 7.1 YAML 格式规范

支持两种组织方式：

**方式一：多工作流文件**（如 `default.yaml`）

```yaml
workflows:
  workflow_name:
    description: 工作流描述
    steps:
      - tool: tool_name
      - tool: another_tool
        condition: "urgency == 'high'"
        with:
          param: value
```

**方式二：独立文件**（如 `my_flow.yaml`）

```yaml
name: my_flow
description: 工作流描述
steps:
  - tool: tool_name
```

### 7.2 字段说明

| 字段                  | 类型     | 说明                               |

| `name`              | string | 工作流名（独立文件必须，须与文件名一致）             |

## 9. RAG 知识库系统

### 9.1 架构

```
文档 (PDF/TXT/MD)
      │
      ▼
_load_text()          提取全文与页码信息（PDF 使用 pypdf）
      │
      ▼
_split_text()         按 500 字符切分，重叠 80，优先在标点处断开
      │
      ▼
embed() 批量嵌入       Ollama nomic-embed-text（每批 32 条）
      │
      ▼
ChromaDB upsert       集合 documents，metadata 含 source/page/chunk_index
      │
      ▼
search()              余弦距离检索，score = 1 - distance
      │
      ▼
answer_question()     拼装上下文 prompt，LLM 生成带来源的答案
```

### 9.2 关键实现

- **路径安全**：`_safe_doc_path()` 限制文件必须位于 `data/rag_docs/` 内，且仅允许 `.pdf/.txt/.md/.markdown`
- **页码元信息**：入库时记录 `page`、`chunk_index`，检索结果可追溯来源
- **分回小说支持**：`ingest_chapter_files()` 按 `第XXX回_标题.txt` 命名规范批量入库，metadata 中增加 `chapter`、
  `chapter_title`
- **查询改写（v2）**：`rag_answer_v2` 将口语化问题改写为原文表达，多路检索后按 score 去重排序，提升召回率
- **防幻觉**：系统提示词强制“只根据文档片段回答，严禁编造”，并要求附带来源

### 9.3 使用流程

1. 将文档放入 `data/rag_docs/`（或通过 UI 上传）
2. 调用 `rag_ingest`（单文件）或 `rag_ingest_chapter_dir`（分回目录）入库
3. 调用 `rag_answer` / `rag_answer_v2` 进行问答

## 10. Excel 自然语言操作

### 10.1 四步流水线

```
excel_describe → excel_plan → excel_execute → excel_answer
 (读取表结构)    (NL→操作计划)   (执行 pandas)    (结果→自然语言)
```

### 10.2 支持的操作类型

`excel_plan` 生成的 `operations` 支持以下操作：

| 类型          | 说明                                                             |
|-------------|----------------------------------------------------------------|
| `filter`    | 条件筛选（`==`、`!=`、`>`、`>=`、`<`、`<=`、`contains`、`in`）              |
| `sort`      | 排序                                                             |
| `select`    | 选择列                                                            |
| `substr`    | 字符串截取                                                          |
| `extract`   | 正则提取                                                           |
| `date_part` | 日期维度提取（year/month/quarter/year_quarter/year_month/day/weekday） |
| `groupby`   | 分组聚合（sum/mean/count/max/min）                                   |
| `top_n`     | 取前 N 条                                                         |
| `dedupe`    | 去重                                                             |
| `fillna`    | 空值填充                                                           |
| `rename`    | 重命名列                                                           |
| `head`      | 取前 N 行                                                         |

### 10.3 设计要点

- **安全路径**：`_safe_excel_path()` 限制文件必须位于 `data/excel/` 内
- **防心算**：`excel_answer` 的 prompt 明确要求所有数字直接来自结果预览，禁止自行计算
- **日期处理**：强制用 `date_part` 处理时间维度，避免用 `rename`/`substr` 伪装
- **错误透传**：每步操作错误记录到 `errors`，`excel_answer` 检测到错误时直接返回错误说明
- **警告机制**：groupby 后行数未减少时提示可能分组键包含唯一值
